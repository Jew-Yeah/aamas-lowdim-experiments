# Независимая двухфазная проверка

[План](two_phase_validation_protocol.json) зафиксирован до новых
разработочных и валидационных прогонов. Это локальная проверяемая фиксация,
а не внешняя предварительная регистрация. Проверяем преимущество быстрой
ветви в простой фазе и защиту после изменения относительно продолжения
fast-only. Постановка мотивирована предыдущим исследовательским аудитом.

## Ресурсная модель и полная цель

Распределяемая мощность `p` лежит в `[0,1]`. Контекст задачи задаёт
эффективность `a` и требуемую работу `b`: `0.5 <= a <= 1`, `0 <= b <= a`.
Нормированный дисбаланс равен `u=a*p-b`; предписанный отклик — `p*=b/a`.
Множество действий противника — `conv{0,e_1,...,e_m}` в исходной евклидовой
геометрии. Нулевой контекст имеет `(a,b)=(1,0)`, коэффициенты продолжаются
аффинно на все смеси. Эффективность на смесях положительна, поэтому выигрыш
отклика в каждой точке всей реализованной оболочки равен нулю. Полная строгая
цель — точно `{0}`; модуль выигрыша на вершинах не превосходит единицы.

Первый контекст нулевой. В первой фазе затем повторяется один контекст с
эффективностью один и отношением необходимой мощности из `[0.02,0.15]`,
независимо выбранным для каждого эпизода. После изменения каждый раунд
приносит новый ортогональный контекст со случайной эффективностью и
потребностью. Функции выигрыша новых типов действительно различаются.
Новизна генерируется извне; обучение реального атакующего не моделируется.

Высокоразмерное представление остаётся существенным ограничением.
Выигрыш зависит всего от двух аффинных коэффициентов. Новый ортогональный
контекст проецируется в наблюдённый нулевой контекст даже при близкой
потребности. Таким образом, опыт проверяет также чувствительность быстрой
ветви к представлению. Это искусственная проверка механизма; она не
обеспечивает репрезентативность для NYC или реальных противников.

## Алгоритмы и сравнения

Сохраняются исходные `G=6*T^(3/4)=24576` при `T=65536`, скалярная блочная
база с `k=1` и её свежий безопасный хвост длины `T-tau`. Раунд пересечения
остаётся быстрым; безопасный режим начинается следующим раундом. Бюджет
произвольно не уменьшаем, повторных перезапусков обучения нет.

Проекционные и седловые задачи быстрой ветви в исходной геометрии решаются
аналитически и проверены независимыми плотными решателями на коротких
траекториях. Четыре угла `(a,b)` используются только для точного вычисления
выигрышей, градиентов и откликов безопасной процедуры. Геометрия быстрой
ветви не сжимается. Скалярные safe-обновления независимо сопоставлены с
`SafeBlockLearner` на произвольных взвешенных траекториях.

В каждом эпизоде сравниваются one-switch, fast-only, block-safe-only,
отклик на предыдущий контекст и среднее последних 16 отношений `b/a`.
Все выбирают действие до текущего наблюдения и начинают с мощности 0.5.
Лаговой эвристике при переменной эффективности не приписывается прежняя
телескопическая гарантия. Будущие наблюдения изменения алгоритмам недоступны.

## Выборка и статистика

Четыре сценария: основное изменение после 16384 раундов, позднее после
32768, более слабое после 16384 и стационарный контроль. В каждом — 200
независимых валидационных эпизодов, seeds 10000--10199; генераторы разных
сценариев имеют разные пространства RNG. Восемь разработочных эпизодов на
сценарий служат проверке реализации и времени, не входят в статистику и
не используются для выбора настроек. Единица наблюдения — полный эпизод;
методы внутри него получают один и тот же внешний путь.

Основное семейство содержит три сравнения в основном сценарии:

1. One-switch минус block-safe-only по среднему расстоянию до изменения.
2. One-switch минус fast-only по конечному расстоянию до полной цели.
3. One-switch минус block-safe-only по конечному расстоянию до полной цели.

Расстояние `delta_t=abs(sum_{s<=t}u_s)/t`. Среднее расстояние до изменения
вычисляется по каждому раунду до заранее заданной границы среды. Средний
модуль дневного дисбаланса — отдельная метрика. Прогоны без переключения
сохраняются во всех сравнениях; границу фаз не определяем по наблюдённому tau.

Для парных разностей применяются двусторонние t-проверки и поправка Holm
на три основных сравнения. Указываются 95% t-интервалы, консервативные
семейные интервалы и bootstrap целых парных эпизодов. Сценарии чувствительности
описываются все, без выбора лучшего. Полосы на кривых — точечные интервалы
среднего, не одновременные полосы и не диапазоны индивидуальных траекторий.
Для стационарного контроля метрика до изменения охватывает весь горизонт.

Нормальное приближение при `n=200` и консервативном `alpha=0.05/3` даёт
около 80% мощности для стандартизованного парного эффекта порядка 0.23.
Это не обещание обнаружить практически важное абсолютное улучшение и
не обобщение на реальную популяцию задач.

Методика соответствует [парным сравнениям NIST](https://www.itl.nist.gov/div898/handbook/prc/section3/prc311.htm)
и принципу парного ресэмплинга из [документации SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html).

## Воспроизведение

```bash
python -m pip install -e ".[test]"
python -m pytest -q
python scripts/run_two_phase_validation.py --stage pilot
python scripts/run_two_phase_validation.py --stage freeze
python scripts/run_two_phase_validation.py --stage validation
python scripts/run_two_phase_validation.py --stage analyze
python scripts/run_two_phase_validation.py --stage figures
```

Для отдельного повтора добавьте ко всем вызовам runner
`--output results/runs/my_two_phase_replay`. Запись выполненных эпизодов не
перезаписывается, изменение зафиксированной реализации блокирует валидацию.
В Git публикуются план и хеши, все сводки эпизодов и итоговые рисунки.
Выборочные точки кривых каждого эпизода и полные траектории двух представителей,
выбранных до запуска, сохраняются локально и воспроизводятся тем же runner;
эти большие массивы исключены из Git. Все метрики рассчитаны по полному ряду;
прореживание рисунков на статистику не влияет.
[Отчёт результатов](../results/two_phase_validation/README.ru.md)
содержит также сравнения, в которых другие методы лучше. Показатели скорости
сходимости не оцениваются; эксперимент `q=4` не добавляется.
