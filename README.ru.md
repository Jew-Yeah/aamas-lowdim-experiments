# Полные траектории one-switch

## Независимая двухфазная проверка

[Новая парная проверка](results/two_phase_validation/README.ru.md) содержит
**800 независимых эпизодов**: четыре фиксированных сценария по 200, с исходной
блочной процедурой и бюджетом. План локально зафиксирован до валидации,
разработочные seeds отделены; сохранены все пять методов. В основном
искусственном сценарии one-switch лучше block-safe по среднему расстоянию
до изменения и лучше fast-only по конечному расстоянию (0,395181 против
0,520319). Однако отдельный block-safe лучше в конце (0,049686), lag и окно
ещё сильнее. Парная статистика с поправкой Holm подтверждает эти разные
направления; общего превосходства или обобщения на реальные задачи нет.
[Методика](docs/two_phase_validation_ru.md) и все сценарии чувствительности
сохраняют также прогоны без переключения. Полные массивы воспроизводятся
локально из опубликованных seeds и кода; в Git большие массивы не включаются.

## Иллюстрация на реальных данных

Иллюстрация статьи проходит **730 последовательных дней долей заявок
NYC**, включая первое пересечение доказанного бюджета и весь безопасный хвост.
Игра использует `u(p,ell)=(p-ell)/sqrt(2)`, эталон `p*(ell)=ell` и полную цель
`{0}`. Отдельно доказанная лаговая процедура даёт консервативный, независимый
от данных бюджет **G=1**. Она отличается от исходной блочной процедуры.
Все методы начинают равномерно и выбирают действие до раскрытия текущих долей;
внутри основного запуска перезапусков нет.

| Метод | Конечное векторное расстояние δ | Средняя суточная норма ошибки |
|---|---:|---:|
| One-switch | 0,000939885 | 0,155910247 |
| Только быстрый режим | 0,000644365 | 0,573865013 |
| Только безопасный lag | 0,000167400 | 0,131152906 |
| Окно, W=16 | 0,001311085 | 0,104084214 |
| Только блочная процедура | 0,034672805 | 0,109093125 |

Master переключается на **44-м раунде**, **2021-02-13**, затем работает **686
безопасных раундов**. Суточная ошибка меньше, чем у непрерывного быстрого режима,
но конечное векторное расстояние у быстрого режима ниже. Lag лучше по конечному
расстоянию, окно — по суточной ошибке. Ошибки разных знаков могут компенсироваться
в среднем векторе; метрики различаются. Доли зарегистрированных заявок задают
модель распределения, но не измеряют потребность в сотрудниках или обслуживание.

Отдельный искусственный тест большой размерности сохраняет **исходную блочную
процедуру и G=6 T^(3/4)**. При `T=16384` пересечение происходит на **8817-м
раунде**. Конечное расстояние равно **0,602296** у master, **0,992126** у быстрого
режима и **0,124300** у отдельного block-safe; lag и окно ещё сильнее. Новые
метки эквивалентны по выплатам. Это проверка механизма, а не скоростей для малой
размерности или общего превосходства.

[Полный отчёт и оба графика](results/switching/README.ru.md) сохраняют все пять
методов, годовые проверки, массивы каждого раунда и хеши.
[Описание методики](docs/switching_ru.md) содержит доказательства бюджетов и
порядок наблюдений. Новые сценарии имеют исследовательский статус после аудита;
для фиксированных рядов не заявляются доверительные интервалы, p-value или
подтверждающая выборка.

## Воспроизведение переключения

Требуется Python 3.10 или выше. Достаточно базовых научных зависимостей.

```bash
python -m pip install -e ".[test]"
python -m pytest -q
python scripts/run_switching_study.py
```

Параметр `--output results/runs/switching_replay` создаёт отдельный повторный
запуск. Скрипт проверяет хеши CSV, воспроизводит три ряда NYC и тест исходного
бюджета, сохраняет английские PNG/PDF. В полной среде разработки **пройдены 152
теста**; без CAGE отдельные проверки симулятора могут пропускаться. Сохранены
[версии базовых зависимостей](requirements-lock.txt) и
[происхождение данных](data/switching_nyc/provenance.json).

## Зафиксированный результат CAGE 2

Сохранённое ниже исследование использует допустимый седловой оракул со скалярным
прогнозом при **W=16 и `rho=0.25`**, выбранных на отдельной валидации. Его данные,
выбор параметров, результаты и статистический смысл не изменены. CAGE — симулятор;
сравниваются политики Window и Hedge.

Средние потери на шаг симулятора по 400 отложенным семенам симуляции и 50 общим
траекториям атакующего длиной 512 раундов выбора политики. Меньше — лучше.

| Метод | Средние потери |
|---|---:|
| Выбранный one-switch со скалярным прогнозом | **1,10418** |
| Настроенное окно, 16 раундов | **1,10154** |
| Настроенный Hedge, множитель скорости обучения 4 | 1,16600 |

Выбранный one-switch снижает потери на **5,3% относительно настроенного Hedge**.
Одновременный 95%-й интервал парной разности составляет `[-0,08010; -0,04421]`.
Окно играет **на 0,24% лучше**: интервал разности one-switch минус окно равен
`[0,00254; 0,00275]`. Во всех 50 тестовых траекториях действия совпадают после
первого раунда. Первые действия различаются: one-switch начинает с равномерной
смеси, окно отвечает на известный начальный режим атаки.

Результат подтверждает близкое к окну качество по скалярным потерям и преимущество
над настроенным Hedge в этой постановке. Превосходства над окном он не
устанавливает. [Исходный отчёт CAGE](results/cage_adaptation/README.ru.md)
содержит графики, хеши данных, зафиксированные параметры и оба основных сравнения.

[Галерея графиков](results/cage_adaptation/figures/README.ru.md) дополняет отчёт
динамикой потерь, накопленными парными разностями, четырьмя компонентами стоимости,
распределением по всем путям, чувствительностью на валидации и векторной ошибкой
относительно полной цели. Доступны PNG/PDF на русском и английском. Эти
описательные дополнения сохраняют выбранные параметры и исходные основные
сравнения.

## Воспроизведение зафиксированного CAGE

Требуется Python версии 3.10 или выше.

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -e ".[test,cage]"
python -m pytest -q
python -m lowdim_games.cli cage-selected --horizon 16 --seeds 41000000 --output results/runs/cage_selected_smoke
```

[Настройка CAGE](docs/cage_ru.md) описывает фиксированную версию симулятора и
меню политик. [Протокол валидации](docs/cage_adaptation_ru.md) сохраняет сетку
параметров, диапазоны семян, порядок выбора, статистический анализ и команды
воспроизведения. Опубликованные агрегированные банки позволяют восстановить
скалярные результаты без повторного сбора эпизодов симулятора.

`cage-selected` запускает рекомендуемый `RecommendedOneSwitchLearner` и два
выбранных метода сравнения без настройки. Короткая команда выше проверяет работу
кода; без `--horizon` и `--seeds` используется зафиксированный запуск
из 50 траекторий по 512 раундов.

## Метод и область применимости CAGE

Алгоритм выбирает действие до раскрытия текущего режима атаки. Прогноз использует
только прошлые наблюдения. Оракул минимизирует прогнозируемые скалярные потери
среди седловых ответов, удовлетворяющих допустимой ошибке рукописи. Оболочка,
обновление направления, целевой ответ и порог переключения из теоремы сохранены.
Подробности — в [математическом описании](docs/algorithms_ru.md).

Все методы получают одну калибровочную таблицу потерь. Метка режима атаки
сообщается после выбора защиты. Один раунд выбирает полную политику для отдельного
50-шагового эпизода с заново инициализированной сетью; показатели смеси усредняют
результаты полных эпизодов. Red выбирает из трёх фиксированных режимов атаки.
Это эксперимент в симуляторе с известной моделью, а не журнал атак действующей сети.

Основной показатель — скалярные потери. Дополнительные графики отдельно измеряют
расстояние до полного векторного целевого множества в фиксированной нормированной
обучающей игре, включая новые запуски на шести объявленных горизонтах. Ошибки
у предела численной точности не позволяют оценить асимптотический порядок
убывания или установить пользу векторной гарантии. Безопасных переключений
на основных траекториях не было. Численные невязки оракулов проверяют точность
вычислений с плавающей точкой и не являются сертификатами в точной арифметике.

## Предыдущие исследования и использование

Сохранённое сравнение CAGE использует первоначально выбранную реализацию.
[Архив полного исследования](https://github.com/Jew-Yeah/aamas-lowdim-experiments/tree/archive/full-study-2026-10-04)
сохраняет предыдущие реализации, результаты и неудачные сравнения, включая
исходный one-switch и исследовательские перезапуски. Эффект перезапусков зависел
от сценария; в рекомендуемую конфигурацию они не входят.
[Коммит снимка](https://github.com/Jew-Yeah/aamas-lowdim-experiments/tree/e8c85cb2e7be49032c1c2d014b6f19084ea064a8)
фиксирует полное исследование до очистки независимо от будущих изменений ветки.
