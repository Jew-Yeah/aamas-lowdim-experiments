# CAGE 2: защита при изменении стратегии атакующего

Этот эксперимент проверяет, помогает ли выбор между готовыми политиками защиты,
когда атакующий меняет поведение между эпизодами. Используется официальный
симулятор CAGE Challenge 2 / CybORG со сценарием сети промышленного предприятия.
Исходные данные получены из эпизодов симулятора с открытым кодом; это не
историческая запись атак на действующую сеть.

Поверх симулятора построена игра выбора политик. Один раунд — новый эпизод
из 50 шагов симулятора. Защитник выбирает распределение по шести фиксированным
политикам до раскрытия текущей политики атакующего. Выбранная политика управляет
всем эпизодом. Потери смеси — среднее исходов целых эпизодов, а не результат
независимого смешивания отдельных действий на каждом внутреннем шаге.

## Фиксированное меню политик

| Политика защиты | Поведение |
|---|---|
| `monitor` | Оригинальный `BlueMonitorAgent` без изменений. |
| `react_remove` | Оригинальный `BlueReactRemoveAgent` без изменений. |
| `react_restore` | Оригинальный `BlueReactRestoreAgent` без изменений. |
| `decoy_cycle` | Циклически размещать восемь штатных типов ложных сервисов на `Op_Server0`, `Enterprise2`, `Enterprise1` и `Enterprise0`; не восстанавливать системы. |
| `critical_restore` | На шагах 1, 4, 7, ... попеременно восстанавливать `Op_Server0` и `Enterprise2`; на остальных шагах выполнять мониторинг. |
| `decoy_react` | Восстанавливать машины с идентификатором процесса в последнем частичном наблюдении Blue, отдавая приоритет четырём указанным критическим машинам; между восстановлениями одной машины выдерживать не менее трёх шагов. В остальных случаях циклически размещать ложные сервисы. |

Последние три политики — явно заданные эвристики этого репозитория.
Они фиксируются до калибровки и не получают истинное состояние заражения
из симулятора. Событие процесса может быть легитимным, поэтому `decoy_react`
иногда восстанавливает систему без необходимости. Неудачное размещение
несовместимого ложного сервиса допускается штатными правилами симулятора
и учитывается в результатах.

Атакующий выбирает между оригинальными `SleepAgent`, `RedMeanderAgent`
и `B_lineAgent`, в таком порядке. Sleep не предпринимает атак. Meander исследует
сеть; B-line использует предварительное знание сети для продвижения к
операционному серверу. В эксперименте обучается выбор готовой атакующей
политики; новые приёмы атаки внутри неё не обучаются. Начальный режим по
умолчанию — Meander. Название фазы «слабый противник» обозначает её место
в сценарии и не утверждает, что Meander причиняет меньший ущерб любой защите.

## Потери и калибровка

Четыре положительные координаты потерь воспроизводят штатную отрицательную
награду:

1. `host_compromise`: привилегированный доступ атакующего к машинам вне
   выделенной группы серверов, включая `Defender`;
2. `server_compromise`: привилегированный доступ к трём серверам Enterprise
   и `Op_Server0`;
3. `operational_disruption`: штраф на каждом шаге, пока операционный сервис
   отсутствует;
4. `restore`: стоимость выполненного действия Restore, включая неудачные
   попытки восстановления.

На каждом шаге проверяется равенство отрицательной суммы восстановленного
вектора штатной скалярной награде. Это единицы награды симулятора, а не деньги.
Потери эпизода усредняются по шагам. Сумма четырёх координат, умноженная
на длину эпизода, равна отрицательной штатной награде за эпизод.

Закреплённая версия сценария задаёт границы координат `(0.8, 4, 10, 1)`.
Весь вектор делится на их евклидову норму `sqrt(117.64)`, поэтому норма
нормированного выигрыша в вершинах не превышает единицу. Эта граница
определяется до наблюдения обучающих и тестовых исходов. Она учитывает
также неудачные действия Restore.

Для каждой из 18 пар «защита — атака» средний вектор оценивается по 40
эпизодам калибровки. Отдельный набор из 40 тестовых эпизодов на пару
используется для оценки фиксированных методов выбора. Начальное состояние
генераторов случайных чисел задаётся до создания нового экземпляра симулятора:
сеть рандомизируется уже при создании. Индексы начальных состояний (seed)
общие для разных пар и позволяют парное сравнение. Политики могут по-разному
расходовать случайные числа, поэтому траектории с одним seed не обязаны
совпадать. Набор по умолчанию содержит 1 440 эпизодов и 72 000 внутренних шагов.

Только средние на калибровке определяют известный тензор, отображение ответа
и обновления алгоритмов. Ответ минимизирует скалярную потерю с равными весами;
при равенстве выбирается действие с наименьшим индексом. Внутри программы веса
нормируются до единичной суммы. Поэтому `mean_test_weighted_loss` — среднее
четырёх исходных координат, а их сумма — штатная суммарная потеря за шаг.

Тестовый набор не участвует в обновлениях защитника или атакующего.
Калибровка, меню политик, скалярные веса и нормировка сохраняются неизменными
во время игры выбора. Изменение этих параметров после просмотра тестовых
результатов требует нового независимого тестового набора.

## Причинные сценарии

Горизонт по умолчанию — 512 раундов выбора политики. Границы трёх фаз
находятся на 25%, 75% и 100% горизонта.

| Сценарий | Протокол атакующего |
|---|---|
| `fixed` | Начальный режим сохраняется весь запуск; по умолчанию это Meander. |
| `curriculum` | Сначала используется начальный режим. В средней фазе по одному предъявляются все три режима, затем они выбираются равномерно. В последней фазе атакующий использует экспоненциальные веса, обученные против фиксированной равномерной смеси защитника. Все методы получают одну и ту же реализованную последовательность. |
| `interactive` | Начальная и средняя фазы устроены так же. В последней фазе атакующий с экспоненциальными весами использует потери предыдущих смесей данного защитника. У каждого метода получается своя последовательность взаимодействия. |

Атакующий накапливает информацию из калибровки во всех трёх фазах.
Распределение последней фазы состоит из 90% экспоненциальных весов
и 10% равномерного исследования. Максимизируется скалярная потеря
с равными весами на калибровке. Шаг обучения равен
`sqrt(8 log(M) / T) / R`, где `R` — общий диапазон скалярных потерь
калибровки. Текущий режим фиксируется по прошлой информации. Защитник
также выбирает действие до получения этого режима.

Все методы выбора знают три атакующие политики и оценённую таблицу потерь.
Текущий режим раскрывается после выбора. Это предположение о полном
наблюдении в игре между эпизодами: частичные наблюдения Blue в оригинальном
сценарии сами по себе не раскрывают метку атакующей политики и все
контрфактические потери. Внутри эпизода фиксированная защита по-прежнему
использует только разрешённые частичные наблюдения. Таким образом,
эксперимент оценивает выбор целых политик при обратной связи на основе
заранее оценённой модели.

## Сравнения

Сравниваются методы статьи `one_switch`, `shared_past_hull` и `block_safe`;
равномерная смесь защит; фиксированный ответ калибровки на начальный режим
(`historical_best`); ответ на последние 16 раскрытых режимов (`last_window`);
Hedge; и все шесть чистых фиксированных защит. Скалярные веса и доступная
обратная связь одинаковы для всех методов.

Hedge минимизирует скалярные потери калибровки с шагом
`sqrt(8 log(K) / T) / R`. Сохраняется граница
`R sqrt(T log(K) / 2)` для суммарного regret на калибровке относительно
лучшей фиксированной политики. Regret означает накопленную разность
потерь метода и этой политики. Тестовый regret вычисляется отдельно
и не покрывается указанной границей. Шаги обучения не подбираются
по тестовому набору.

Быстрый метод по прошлой выпуклой оболочке является общим с геометрическим
методом, обсуждаемым при сравнении статьи с Marinov et al. Алгоритм с одним
переключением использует исходный бюджет
`G_T = 6 sqrt(K - 1) T^(3/4)`. В этом эксперименте каждый раскрытый режим
является чистым действием. Вне прошлой оболочки может оказаться только первое
появление режима, поэтому суммарная невязка не превышает `2(M - 1) = 4`.
Переключение по умолчанию невозможно на таких последовательностях при любом
горизонте. Действия `one_switch` и `shared_past_hull` должны совпадать.
Эти запуски проверяют адаптацию быстрого метода, а не механизм безопасного
переключения.

## Оценка и интерпретация

Прикладные результаты — четыре тестовые координаты потерь, их скалярная
комбинация и показатели отдельных фаз. Каждый метод также сравнивается
с лучшей фиксированной политикой на своей реализованной последовательности.
В интерактивном сценарии это описательный повторный расчёт: фактическое
применение этой фиксированной политики обычно изменило бы будущую
последовательность атак. Сравнение интерактивных результатов разных методов
относится к целым взаимодействиям при одном правиле атакующего.

Расстояния до цели вычисляются в калиброванной игре с её фиксированным
отображением ответа. Учитывается полная цель ответов на реализованной
оболочке; невязки проверяются независимыми LP для опорной функции.
Второе расстояние использует всю библиотеку из трёх режимов как общую цель.
Такая цель может быть менее строгой, чем цель реализованной оболочки.
Оба расстояния следует показывать вместе с прикладными потерями: уменьшение
расстояния само по себе не устанавливает улучшение безопасности или снижение
стоимости восстановления. Аффинная размерность противника не превышает двух
из-за заданного меню. Это свойство постановки, а не вывод о размерности
настоящих кибератак.

Для тестового набора вычисляются условные 95% интервалы Стьюдента.
При фиксированной обученной последовательности доли использования пар
«защита — атака» взвешивают всю таблицу потерь для каждого тестового seed.
Парные разности используют совпадающие индексы seed. Число независимых
наблюдений равно числу тестовых seed; повторное использование средних
в 512 раундах не создаёт 512 новых запусков симулятора. Интервалы условны
на калибровку и последовательности и не учитывают неопределённость самой
калибровки. Это приближённые статистические интервалы, а не формальные
численные сертификаты.

Конечный тензор оценён методом Монте-Карло. Гарантии и численные проверки
цели относятся к полученной калиброванной игре; они не доказывают гарантии
для неизвестных точных математических ожиданий симулятора. Это поисковый
эксперимент с небольшим меню фиксированных эвристик. Его результаты нельзя
напрямую сопоставлять с таблицей исходного соревнования и его обученными
RL-агентами.

## Воспроизведение

Выполняйте команды из корня репозитория. Версия внешних исходников закреплена;
калибровка отклоняет изменения отслеживаемых файлов в них.

```bash
python -m pip install -e ".[test,cage]"
git clone https://github.com/cage-challenge/cage-challenge-2 .external/cage-challenge-2
git -C .external/cage-challenge-2 checkout 26ce1c1253fa9e2e73f25e6a7f2da32860c11257
python -m lowdim_games.cli cage-calibrate --steps 50 --train-episodes 40 --test-episodes 40 --seed 20261003 --output data/cage2
python -m lowdim_games.cli cage --calibration data/cage2 --scenarios fixed curriculum interactive --horizon 512 --seeds 20261003 20261004 20261005 --initial-red-index 1 --plots
python -m pytest -q
```

Seed калибровки: от `20261003` до `20261042`; тестовые seed:
от `21261003` до `21261042`. Три seed игры выбора управляют выборкой режимов
и не создают дополнительных наборов калибровочных эпизодов.

`data/cage2/calibration.npz` содержит раздельные наборы эпизодов, средние
по парам, нормированный тензор, названия политик, веса и seed.
`provenance.json` сохраняет чистую версию внешнего кода, хеши исходников,
проверки восстановления награды, единицы и версии программ.
`cell_statistics.json` содержит средние, стандартные отклонения
и стандартные ошибки. Каждый запуск сохраняет манифест, действия,
режимы атак, выигрыши, доли использования пар и численные невязки
в `results/runs/cage2`. Замеры времени включают последующую оценку.

[Опорный отчёт](../results/cage_reference/README.ru.md) содержит завершённые
запуски и измеренные результаты. Описание методики само по себе не утверждает
преимущества какого-либо метода.
