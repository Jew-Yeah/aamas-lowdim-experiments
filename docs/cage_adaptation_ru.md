# Выбор saddle-ответа по прогнозу и перезапуски по блокам

Исследование проверяет два изменения реализации в калиброванной игре CAGE 2: выбор допустимого saddle-ответа с учётом прогноза атак и перезапуск one-switch по блокам. Исходная статья, исходные алгоритмы и предыдущие отчёты сохранены. [Протокол](cage_adaptation_protocol.json) зафиксирован до оценки валидационных результатов.

## Выбор ответа по прогнозу

Пусть B — матрица выплат в текущем направлении на полной оболочке прошлых действий противника. Сначала вычисляется исходное minimax-распределение z* противника и L = min_a (B z*)_a. Среди вероятностных векторов, удовлетворяющих

```text
B.T @ p <= L + rho / sqrt(t),    0 <= rho <= 1,
```

выбирается ответ с минимальными калиброванными скалярными потерями против частот предыдущих W режимов атаки. Свидетель целевой точки z*, полная оболочка, проекция, обновление направления и сертифицированный бюджет переключения сохраняются. Первый ход остаётся равномерным, как в исходной реализации.

Ограничение даёт saddle gap не больше rho/sqrt(t), то есть укладывается в допуск статьи. Код независимо пересчитывает фактический gap, записывает численные превышения и возвращается к исходной паре при неудаче проверки LP. Проверки в арифметике с плавающей точкой дают численное свидетельство, а не формальный сертификат в точной арифметике. Это выбор реализации оракула; новая теорема сходимости не заявляется.

## Валидация и финальная оценка

Обучающая модель — исходная калибровка по 40 семенам в data/cage2. Эпизод содержит 50 внутренних шагов. Меню из шести защит и трёх режимов атаки сохранено. Метрика — нативная сумма четырёх компонент потерь; меньше означает лучше.

Новая валидация использует 100 семян 38000000–38000099 и 20 общих последовательностей 40000000–40000019 при горизонте 512 раундов. Сетка:

- Оракул по прогнозу: W из {4, 8, 16, 32, 64}, rho из {0, 0.25, 0.5, 1}.
- Оконная стратегия: те же пять размеров окна.
- Hedge: множители {0.25, 0.5, 1, 2, 4} исходного шага обучения.

В каждой группе выбирается конфигурация с минимальными средними нативными потерями на валидации; точные равенства разрешаются порядком сетки. Конфигурации и хеши валидационных входов сохраняются в selection.json до чтения финальных результатов.

Финальная выборка содержит 400 новых семян 39000000–39000399. Пятьдесят новых общих последовательностей 41000000–41000049 проверяют зафиксированные параметры при горизонте 512. Два первичных сравнения: выбранный оракул против выбранного окна и выбранного Hedge. Используется 10 000 парных перекрёстных бутстрэп-выборок, seed 44000000, с одновременным семейным уровнем 95% по Bonferroni. Перевыбираются целые таблицы семян симулятора и целые последовательности. Интервалы приближённые и условны на модели и выбранных параметрах; неопределённость обучения в них не включена. Преимущество требует интервала строго ниже нуля для разности «наш минус базовый». Предыдущие тестовые результаты не участвуют в выборе параметров.

## Блоки

Блок содержит 1000 раундов выбора политики; каждый раунд — целый эпизод с новым состоянием симулятора. Горизонт 3000 даёт три блока. Здесь нет сети, непрерывно работающей 3000 внутренних шагов.

Оба варианта сохраняют калибровку. На границе блока сбрасываются направление, накопленный остаток, безопасный режим и локальное время. Бюджет вычисляется для фактической длины нового блока:

- Свежая история: оболочка и история для прогноза очищаются.
- Сохранённая история: все ранее раскрытые режимы, включая наблюдения безопасного хвоста, сохраняются при сбросе состояния алгоритма.

Первый ход каждого блока остаётся равномерным. Для исходного и выбранного оракула проверяются оба перезапуска; также приводятся выбранные окно и Hedge. Двадцать последовательностей curriculum начинаются с seed 42000000. Ещё двадцать начинаются с 43000000 и чередуют Meander и B-line каждые 500 раундов. Используется та же новая финальная выборка симулятора. Сравнения перезапусков вторичны; для них приводятся описательные парные интервалы 95%.

Чередование детерминировано: двадцать повторов совпадают и не создают двадцать независимых источников вариативности пути.

Сброс только счётчика остатка при сохранении остальных состояний не меняет действия, пока порог не пересекается. Полный перезапуск может менять действия. Его гарантия складывается по блокам; при фиксированной длине блока исходная скорость сходимости по общему горизонту не переносится автоматически. См. [теоретическую заметку](cage_restart_theory_ru.md).

## Границы интерпретации

Это эксперимент в симуляторе с известной калиброванной моделью. Противник обучается выбору среди трёх фиксированных режимов; режим раскрывается после выбора защиты. Смеси означают ожидаемые результаты целых эпизодов с новым состоянием сети. Результаты не описывают журналы настоящих атак или сеть с состоянием, сохраняющимся между раундами метаигры.

Настройка может дать равенство с сильным оконным методом без доказанного превосходства над ним. Отчёт показывает оба первичных сравнения и фактические числа переключений и перезапусков. Снижение скалярных потерь также не доказывает уменьшения расстояния до векторной цели; в расширении целевая геометрия не пересчитывается.

## Воспроизведение

Используйте закреплённый симулятор и зависимости из [инструкции CAGE](cage_ru.md). Команды заново собирают отдельные выборки и последовательно выполняют валидацию, фиксацию параметров, финальные траектории, перезапуски и анализ:

```bash
python scripts/collect_cage_bank.py --steps 50 --seed 38000000 --count 100 --partition external --exclude-calibration data/cage2 --workers 4 --output results/runs/cage_adaptation/banks/validation50
python scripts/collect_cage_bank.py --steps 50 --seed 39000000 --count 400 --partition heldout --exclude-calibration data/cage2 --workers 8 --output results/runs/cage_adaptation/banks/test50
python scripts/run_cage_adaptation_study.py --stage all --workers 8 --output results/runs/cage_adaptation/selection
python scripts/build_cage_adaptation_report.py
```

Полные контрольные файлы путей остаются в игнорируемой рабочей папке. Опубликованные выборки, параметры, валидационные оценки, агрегаты посещений и графики позволяют пересчитать скалярные сравнения. Продолжать запуск по контрольным файлам можно только при прежнем коде, протоколе и калибровке. Для новой конфигурации используется новая выходная папка.
