# Выбранная реализация: валидация и финальный тест

Основной отчёт представляет непрерывный one-switch со скалярным прогнозом,
**W = 16, rho = 0.25**, настроенное окно 16 и Hedge с множителем скорости
обучения 4. Параметры выбраны на валидации до чтения финальных результатов.
Сохранены [исходный протокол](cage_adaptation_protocol.json),
[зафиксированный выбор](../results/cage_adaptation/selection.json) и
[сетка валидации](../results/cage_adaptation/validation_grid.json).

## Оракул и методы сравнения

Оракул со скалярным прогнозом минимизирует калибровочные потери против недавних
частот режимов среди седловых ответов, удовлетворяющих
`B.T @ p <= L + rho / sqrt(t)`. Сохранены исходные двойственный минимаксный ответ,
полная прошлая оболочка, обновление направления, равномерный первый ход и порог
переключения из теоремы. Неуспешная проверка кандидата возвращает исходную
седловую пару. См. [математическое описание](algorithms_ru.md).

Окно прямо отвечает на частоты последних W раскрытых режимов. До первого
наблюдения оно отвечает на известный начальный режим Meander. Hedge обновляет
экспоненциальные веса защит по тем же калибровочным скалярным потерям; исходная
формула скорости обучения умножается на выбранный коэффициент. Все методы
имеют одинаковую обучающую информацию и узнают метку атаки после выбора.
При обновлениях финальные результаты симуляции им не доступны.

## Раздельные банки и фиксирование выбора

Неизменённая обучающая модель использует по 40 семян симуляции в `data/cage2`
для каждой из 18 пар защиты и атаки. Каждый эпизод длится 50 шагов. Основной
показатель — сумма четырёх штатных координат потерь на шаг; меньше — лучше.

Новые банки содержат:

| Банк | Семена симуляции | Назначение |
|---|---|---|
| Валидация | 38000000–38000099, 100 семян | Выбор конфигураций |
| Финальный тест | 39000000–39000399, 400 семян | Финальная оценка качества |

Всего **9000 новых эпизодов симулятора и 450000 шагов**. Индексы семян общие
для всех пар политик. При анализе парность сохраняется на уровне целых таблиц;
разные политики могут потреблять случайные числа по-разному.

Валидация проверяет 20 общих траекторий со сменой режимов, семена
40000000–40000019, горизонт 512. Заявленная сетка содержит 30 конфигураций:

- Оракул со скалярным прогнозом: W из {4, 8, 16, 32, 64}, rho из {0, 0.25, 0.5, 1}.
- Окно: те же пять значений W.
- Hedge: множители {0.25, 0.5, 1, 2, 4} исходной скорости обучения.

Для каждого семейства выбираются минимальные средние валидационные потери.
Точные совпадения разрешаются порядком сетки. Хеши данных и реализации вместе
с параметрами зафиксированы до доступа к финальным оценкам. Исходные и
исследовательские сравнения не определяют выбор. После просмотра финальных
результатов параметры и первый ход не менялись.

## Финальные сравнения

Пятьдесят новых общих траекторий, семена 41000000–41000049, проверяют выбранные
конфигурации на горизонте 512. Два основных сравнения — выбранный one-switch
минус настроенное окно и выбранный one-switch минус настроенный Hedge.
Парный перекрёстный бутстреп пересэмплирует целые таблицы семян симуляции и
целые траектории: 10000 повторов, семя 44000000. Поправка Бонферрони даёт
примерно 95%-е одновременное покрытие для двух интервалов.

| Метод | Средние штатные потери |
|---|---:|
| Выбранный one-switch | 1,1041833342 |
| Настроенное окно | 1,1015373414 |
| Настроенный Hedge | 1,1660012489 |

| Сравнение | Средняя разность | Одновременный 95%-й интервал |
|---|---:|---:|
| One-switch − окно | +0,0026459928 | [+0,0025386010; +0,0027535403] |
| One-switch − Hedge | −0,0618179146 | [−0,0800977015; −0,0442132772] |

Выбранный метод улучшает результат настроенного Hedge примерно на 5,3%;
потери окна примерно на 0,24% ниже. На всех 50 тестовых траекториях действия
one-switch и окна **точно совпадают после первого раунда**. Всю разницу
объясняет первый равномерный ход one-switch. Начальный ход по известному
режиму не входил в зафиксированный эксперимент. В основном тесте нет
безопасных переключений, откатов оракула и превышений номинального допуска
седлового зазора. [Диагностика траекторий](../results/cage_adaptation/trace_diagnostics.json)
сохраняет сравнение действий и хеши контрольных файлов.

Интервалы приближённые и условны относительно исходной обучающей модели
и выбранных параметров. Они не включают неопределённость обучения и выбора
модели. Повторное использование средних таблицы на 512 ходах не создаёт
512 новых независимых эпизодов симулятора.

## Воспроизведение опубликованного анализа

После [установки пакета](cage_ru.md) основной отчёт восстанавливается
по опубликованным агрегатам:

```bash
python scripts/build_cage_adaptation_report.py --run-dir results/cage_adaptation --bank-root data/cage2_adaptation --output results/runs/focused_report
```

Сборщик проверяет хеши банков, выбранных параметров и агрегатов, независимо
восстанавливает основные средние, сохраняет оба сравнения и создаёт графики
PNG/PDF. Исходный агрегированный файл содержит шесть методов основного
запуска; оформление сосредоточено на трёх выбранных методах.

Повторный запуск выбранных траекторий без настройки:

```bash
python -m lowdim_games.cli cage-selected --output results/runs/cage_selected
```

Для короткой функциональной проверки добавьте `--horizon 16 --seeds 41000000`.
Короткий запуск не подтверждает зафиксированное статистическое сравнение.

Воспроизведение исходных этапов валидации и теста по публичным банкам:

```bash
python scripts/run_cage_adaptation_study.py --stage validation --bank-root data/cage2_adaptation --output results/runs/cage_adaptation_replay --workers 8
python scripts/run_cage_adaptation_study.py --stage select --bank-root data/cage2_adaptation --output results/runs/cage_adaptation_replay
python scripts/run_cage_adaptation_study.py --stage test --bank-root data/cage2_adaptation --output results/runs/cage_adaptation_replay --workers 8
```

Чистый симулятор зафиксированной версии нужен только для повторного сбора:

```bash
python scripts/collect_cage_bank.py --steps 50 --seed 38000000 --count 100 --partition external --exclude-calibration data/cage2 --workers 4 --output results/runs/recollected_banks/validation50
python scripts/collect_cage_bank.py --steps 50 --seed 39000000 --count 400 --partition heldout --exclude-calibration data/cage2 --workers 8 --output results/runs/recollected_banks/test50
```

Полные контрольные файлы траекторий остаются в игнорируемых каталогах запусков.
Изменённая конфигурация требует нового каталога. Зафиксированные сборщик
траекторий и модули алгоритмов побайтово совпадают с использованными при
выборе параметров и тестировании.

## Очистка оформления и ограничения

Главная ветка сосредоточена на проверенном основном результате.
[Неизменяемый снимок полного исследования](https://github.com/Jew-Yeah/aamas-lowdim-experiments/tree/e8c85cb2e7be49032c1c2d014b6f19084ea064a8)
и [архивная ветка](https://github.com/Jew-Yeah/aamas-lowdim-experiments/tree/archive/full-study-2026-10-04)
сохраняют предыдущие приложения, результаты исходного метода и все исследования
перезапусков. Исходный one-switch имел более высокие скалярные потери.
Перезапуски помогали ему при чередовании атак, но ухудшали результат при
постепенном изменении; они исследовательские и не входят в рекомендуемую
конфигурацию. Исходный протокол и основные необработанные агрегаты сохранены
в главной ветке.

Измеряется выбор политик по известной модели в отдельно инициализированных
эпизодах симулятора. Red выбирает фиксированные режимы, метка раскрывается
после выбора. Эксперимент не проверяет журналы атак действующей сети,
сохранение состояния сети между раундами, новые обученные тактики или
превосходство по векторному расстоянию. Диагностика оракулов численная.
Исходная рукопись не редактировалась.
